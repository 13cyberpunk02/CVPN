# CVPN

Десктопный клиент sing-box для Windows на WPF. Собирает `config.json` за вас,
запускает ядро и показывает, что происходит с трафиком.

Поддерживаются **VLESS (Reality и WebSocket)**, **AnyTLS** и **NaiveProxy**,
а маршрутизация настраивается правилами: какие сайты идут через прокси,
какие напрямую, а какие блокируются.

> Проект не связан с командой sing-box. Это отдельная обёртка над официальным ядром.

## Возможности

- Подключение по VLESS+Reality, VLESS+WebSocket, AnyTLS и NaiveProxy
- Импорт профилей по ссылке (`vless://`, `anytls://`, `naive+https://`) и из готового `config.json`
- Правила маршрутизации: geosite, geoip, домен, суффикс домена, ключевое слово, имя процесса
- Свои наборы правил `.srs` - по ссылке или файлом с диска
- Два режима перехвата: TUN и системный прокси Windows
- Живые счётчики приёма и отдачи, замер задержки до сервера
- Вывод ядра в реальном времени с автопрокруткой
- Подробный лог с разбором того, какое правило сработало
- Проверка конфигурации до запуска - ошибка видна сразу, а не в логе

## Требования

| | |
|---|---|
| ОС | Windows 10 версии 1809 или новее / Windows 11 |
| Среда | [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) |
| Ядро | [sing-box](https://github.com/SagerNet/sing-box/releases) **1.12 или новее** |

Версия ядра важна. В 1.12 из sing-box убрали `geosite` и `geoip` в правилах маршрутизации,
заменив их механизмом rule-set, а спецвыходы `block` и `dns` - действиями правил.
CVPN генерирует конфигурацию в новом формате, и на 1.11 она не запустится.

## Установка

**1. Поставьте .NET 10 Desktop Runtime**, если его ещё нет.

**2. Скачайте sing-box** для Windows с
[страницы релизов](https://github.com/SagerNet/sing-box/releases) и распакуйте.

**3. Положите ядро рядом с приложением** - в подпапку `core`:

```
CVPN/
├── CVPN.exe
└── core/
    └── sing-box.exe
```

Либо укажите любой другой путь в настройках через кнопку «Обзор».

**4. Для NaiveProxy дополнительно** положите `libcronet.dll` рядом с `sing-box.exe`.
Этот протокол работает через сетевой стек Chromium, и без библиотеки ядро откажется
стартовать. Для VLESS и AnyTLS она не нужна.

Готовность проверяется в заголовке окна: там должна появиться версия ядра
вместо «ядро не найдено».

## Сборка из исходников

```bash
git clone https://github.com/<user>/CVPN.git
cd CVPN
dotnet restore
dotnet build -c Release
dotnet run
```

Единственная внешняя зависимость - [SolimusWrapper](https://www.nuget.org/packages/SolimusWrapper)
для запуска ядра и чтения его вывода.

## Быстрый старт

1. **Профили** → вставьте ссылку в поле и нажмите «Разобрать ссылку».
   Либо «Импорт из файла», если у вас есть готовый `config.json`.
2. Нажмите **«Выбрать»** на нужном сервере - у него появится рамка акцентного цвета.
3. **Соединение** → нажмите круг по центру.
4. При включённом TUN появится запрос прав администратора. Согласитесь -
   приложение перезапустится с повышением.

Название профиля, протокол и задержка в миллисекундах отображаются прямо внутри круга.
Обод показывает состояние: серый - отключено, индиго с бегущим сегментом - подключение,
нефритовый - работает, красный - ошибка.

## Профили

### Импорт по ссылке

```
vless://uuid@host:443?security=reality&pbk=<public_key>&sid=<short_id>&sni=www.google.com&flow=xtls-rprx-vision#Название
vless://uuid@host:443?type=ws&security=tls&path=/ws&host=example.com#Название
anytls://password@host:8443?sni=example.com#Название
naive+https://user:password@host:443#Название
```

### Подписка

Вставьте ссылку подписки в поле на странице «Профили» и нажмите «Обновить
подписку». Понимается стандартный формат: список ссылок построчно, целиком
закодированный в base64 (без кодирования тоже работает).

Обновление заменяет только профили, пришедшие из этой же подписки - они помечены
в списке. Созданные вручную не трогаются. Выбранный сервер сохраняется по имени,
если он остался в новом списке.

### Переключение без перезапуска

Все серверы попадают в конфигурацию сразу, а выбор делает селектор sing-box.
Поэтому нажатие «Выбрать» на другом профиле переключает туннель через Clash API
за миллисекунды - ядро не перезапускается, живые соединения не рвутся.

Настройка «Автовыбор быстрого сервера» передаёт выбор механизму urltest: ядро
само проверяет серверы раз в три минуты и держит соединение на быстрейшем.
Переключение происходит, только если новый быстрее предыдущего минимум на 50 мс -
иначе туннель прыгал бы между узлами с близкой задержкой.

### Проверка серверов

Кнопка «Проверить все» замеряет время TCP-рукопожатия до каждого сервера
параллельно. Работает и без подключения - тем и отличается от кнопки «Замерить
задержку» на странице соединения, которая гоняет запрос через поднятый туннель
и показывает реальную задержку до целевого сайта.

### Импорт из JSON

Кнопка «Импорт из файла» принимает три формы:

- полный конфиг sing-box - вытащит все прокси-outbound'ы разом;
- массив outbound-объектов;
- один outbound-объект.

Всё, что не относится к поддерживаемым протоколам (`direct`, `selector`, `urltest`),
пропускается молча. Чужой рабочий конфиг можно скормить целиком.

### Код страны

Значок страны в круге определяется автоматически - по названию профиля
(«Netherlands», «Франкфурт») или по хосту вида `nl-01.example.net`.
Не угадал - значок просто скрывается.

Значок буквенный, а не флаг: Windows не отрисовывает флаги-эмодзи из regional
indicator, показывая вместо них две буквы. Так что это то же самое, но предсказуемо.

## Экспорт

Кнопка «Поделиться» на карточке профиля открывает окно со ссылкой и QR-кодом.
Формат тот же, что понимают другие клиенты, - ссылку можно передать как есть.

«Экспорт всех» отдаёт весь список одной строкой в формате подписки (base64).
Такую строку принимает большинство клиентов, включая CVPN.

## Режимы работы

Текущий режим всегда виден слева внизу.

### TUN

Создаёт виртуальный сетевой интерфейс и перехватывает **весь** трафик системы,
включая приложения, которые ничего не знают про прокси.

Требует прав администратора - иначе интерфейс не создать. CVPN предложит
перезапуск с повышением, когда это понадобится.

### Системный прокси

Прописывает `127.0.0.1:<порт>` в настройки прокси Windows. Прав администратора
не требует, но работает только для приложений, которые эти настройки учитывают:
браузеры, большинство мессенджеров.

Настройки возвращаются к прежним при отключении, при закрытии приложения
и даже при аварийном завершении ядра. Локальные адреса идут мимо прокси.

> Если переключить режим при активном соединении, подпись предупредит:
> изменение применится только после переподключения. Ядро перечитывает
> конфигурацию исключительно при перезапуске.

## Маршрутизация

Правила проверяются **сверху вниз, первое совпадение решает судьбу соединения**.
Что делать с остальным трафиком - задаётся отдельно внизу страницы.

| Тип | Что вводить | Пример |
|---|---|---|
| `geosite` | имя категории | `youtube`, `twitch`, `category-ads-all` |
| `geoip` | код страны | `ru`, `de`, `us` |
| `domain` | точное совпадение | `example.com` |
| `domain_suffix` | домен и все поддомены | `openai.com` |
| `domain_keyword` | подстрока в имени домена | `google` |
| `process_name` | имя исполняемого файла | `Telegram.exe` |
| `rule_set · ссылка` | URL готового набора | `https://.../geosite-youtube.srs` |
| `rule_set · файл` | путь к файлу | `C:\rules\twitch.srs` |

Действия: **через прокси**, **напрямую**, **блокировать**.

### Про наборы .srs

`geosite` и `geoip` подтягиваются с официальных репозиториев SagerNet автоматически.
Скачивание идёт **через туннель**, потому что `raw.githubusercontent.com` часто
недоступен напрямую, а результат кэшируется - загрузка разовая.

Обратная сторона: при первом запуске с новым правилом нужен живой прокси,
иначе ядро не стартует.

Свои наборы подключаются через `rule_set`. Локальные `.srs` читаются по
абсолютному пути - при переносе на другую машину файл нужно взять с собой.

### Наборы правил

В правом верхнем углу страницы «Маршруты» переключаются именованные наборы.
Каждый хранит свои правила и своё значение «всё остальное» - удобно держать
раздельно, например, «всё через прокси» и «только заблокированное».

Смена набора требует переподключения: маршруты живут в конфигурации ядра,
в отличие от выбора сервера, который меняется через Clash API на лету.

### Стартовый набор

При первом запуске создаются два правила: реклама (`geosite:category-ads-all`)
в блок и российские адреса (`geoip:ru`) напрямую. Удалить или изменить их можно
как любые другие.

## Автозапуск

Переключатель в настройках прописывает приложение в раздел `Run` текущего
пользователя. Запуск идёт с аргументом `--minimized`: окно не показывается,
работает только значок в трее.

Отдельная настройка «Подключаться при запуске» сразу поднимает туннель с
последним выбранным профилем. В связке с TUN появится запрос прав администратора,
поэтому для полностью автоматического старта разумнее либо выключить TUN,
либо соглашаться на UAC вручную.

## Где лежат файлы

```
%APPDATA%\CVPN\
├── profiles.json     профили, правила и настройки
├── config.json       генерируется при каждом подключении
├── cache.db          кэш ядра: наборы правил и DNS
└── rules/            копии локальных .srs
```

Локальные наборы правил копируются в `rules/` при добавлении - так профиль
не сломается, если исходный файл переместят.

`config.json` **перезаписывается при каждом запуске** - править его руками
бессмысленно, изменения затрутся. Посмотреть, что получилось, можно кнопкой
«Открыть config.json» на странице соединения.

## Что генерируется в config.json

Несколько решений, о которых стоит знать, если будете сверять с чужими конфигами.

**Адрес сервера резолвится мимо туннеля.** На прокси-outbound проставляется
`domain_resolver` с локальным резолвером - иначе получается замкнутый круг:
чтобы подключиться к серверу, нужно узнать его адрес, а для этого нужен туннель.
DNS-правило с `outbound: "any"`, которое раньше решало ту же задачу, устарело
в 1.12 и удалено в 1.13.

**Блокировка - это действие, а не выход.** Правила с блокировкой получают
`"action": "reject"`. Спецвыход `block` из ядра убран.

**Определение протокола до маршрутизации.** Первым правилом идёт `"action": "sniff"`,
без него доменные правила не сработают для соединений, пришедших из TUN по IP.

**Частные адреса всегда напрямую.** Правило `ip_is_private` стоит выше
пользовательских - локальная сеть не должна уходить в туннель.

**DNS.** Удалённый резолвер по умолчанию - DoH на 443 порту. DoT (853) через
прокси часто висит до таймаута: этот порт режут и провайдеры, и сами
прокси-серверы. Транспорт задаётся схемой в настройках: `https://`, `tls://`,
`quic://`, `udp://`. Локальный резолвер - системный (`type: "local"`).

Домены из правил «напрямую» резолвятся локально: иначе запрос уходит через
туннель, а сайт с геобалансировкой отдаёт адрес узла рядом с выходной нодой.

**Clash API** поднимается на `127.0.0.1:9191` - оттуда берутся счётчики трафика
(веб-сокет `/traffic`) и замер задержки (`/proxies/proxy/delay`).

## Решение проблем

### «ядро не найдено» в заголовке

Путь к `sing-box.exe` указан неверно. Настройки → «Обзор».

### Конфигурация отклонена ядром

Текст ошибки от sing-box показывается целиком - читайте его, там указано поле.
Самая частая причина: ядро версии 1.11 или старее, которое не понимает
`rule_set` и `action`. Проверьте `sing-box version`.

### Подключились, но интернета нет

Посмотрите режим слева внизу. Если это системный прокси - работать будут только
браузеры и приложения, читающие настройки Windows. Для остального нужен TUN.

### TUN не включается

Нужны права администратора. Приложение предложит перезапуск при попытке
подключиться. Если отказались - включится системный прокси.

### Приложение не запускается через `dotnet run`

Так и должно быть, если вернуть в манифест `requireAdministrator`: `dotnet run`
стартует процесс через `CreateProcess`, который не умеет показывать запрос UAC,
и падает с ошибкой 740. В репозитории манифест намеренно оставлен `asInvoker`,
а повышение делается перезапуском в рантайме.

### В логе ошибки о `192.168.x.x` по таймауту

Это обращения к устройствам локальной сети - сетевым папкам, принтерам, роутеру.
Правило `ip_is_private` отправляет их напрямую, и если устройство недоступно,
соединение отваливается по таймауту. К туннелю отношения не имеет.

### Сайт идёт не через тот выход

Включите «Подробный лог» в настройках и найдите строки с нужным доменом:

```
router: match[0] => sniff                                    определение протокола
router: match[1] protocol=dns => hijack-dns                  перехват DNS
router: match[3] rule_set=geosite-category-ru => route(direct)   ваше правило
outbound/direct[direct]: outbound connection to 87.240.185.168:443
```

Индексы 0–2 занимают служебные правила, пользовательские начинаются с третьего.
Если совпадения с вашим правилом нет, а соединение ушло в `proxy` - домена
просто нет в наборе.

Частая причина: сайт живёт не в той зоне, что вы предполагаете. Например,
`2ip.ru` переехал на `2ip.io`, и в списке российских сайтов зоны `.io` нет.
Проверяется за минуту - добавьте правило `domain_suffix` с этим доменом
и посмотрите, изменится ли выход.

Для домена, который резолвится верно, но приезжает на чужой сервер, смотрите
строку `dns: match[...] => route(dns-local)`. Её отсутствие означает, что запрос
ушёл через туннель, и сайт с геобалансировкой отдал адрес ближайшего к выходной
ноде узла. DNS-правила создаются автоматически для правил «напрямую» с доменным
условием - но не для `geoip`, потому что на момент запроса адреса ещё нет.

### Наборы правил не скачиваются

Они качаются через туннель, так что при первом подключении прокси должен быть
рабочим. Если сервер недоступен, ядро не стартует. Уберите правила с geosite/geoip,
подключитесь и верните обратно.

## Архитектура

```
Theme/          токены дизайна и стили контролов
Controls/       ConnectDial - круг подключения
Views/          Соединение · Профили · Маршруты · Логи · Настройки
ViewModels/     MainViewModel - состояние приложения
Models/         ServerProfile, RouteRule, перечисления
Services/       ConfigBuilder, LinkParser, ConfigImporter, ProfileStore,
                SingBoxService, ClashApiClient, SystemProxy, AppPaths
Core/           Mvvm (ObservableObject, RelayCommand), Elevation
```

Все цвета живут в `Theme/Palette.xaml` - ниже по коду литеральных цветов нет,
смена палитры это правка одного файла.

MVVM реализован вручную в `Core/Mvvm.cs`: при таком объёме логики тянуть
CommunityToolkit незачем.

### Полезно знать при доработке

Внутри `Style` и `ControlTemplate` **не работают** `ElementName` и
`Storyboard.TargetName` - у них нет доступа к области имён. Используйте
`RelativeSource AncestorType` и пути свойств вида
`(UIElement.RenderTransform).(RotateTransform.Angle)`.
