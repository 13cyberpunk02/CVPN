# Локализация: как переводить дальше

Инфраструктура готова, страница логов и навигация переведены как образец.
Осталось около 400 строк - переносите по одной странице, собирая после каждой.

## Как устроено

```
CVPN/Localization/
├── Loc.cs            менеджер и разметочное расширение
├── Strings.resx      английский, нейтральный
└── Strings.ru.resx   русский перевод
```

**Английский - нейтральный язык.** Это не формальность: если перевода нет,
показывается английская строка, а не пустое место. Русский собирается
в сателлитную сборку `ru\CVPN.resources.dll`.

Язык берётся из настроек и применяется в `App.OnStartup` до создания окна.
Пустая строка означает язык системы.

## Почему без Strings.Designer.cs

Обычно Visual Studio генерирует по `.resx` класс со свойствами, и ключи
проверяются компилятором. Я от этого отказался: файл генерируется только
средой, и проект переставал бы собираться одной командой `dotnet build`.

Взамен потерянную проверку восстанавливает `LocalizationTests`: он сверяет
все ключи, встреченные в разметке и коде, с содержимым ресурсов, следит
за полнотой перевода и за совпадением подстановок вроде `{0}`.

Опечатка в ключе не роняет приложение - на экране появится `[Ключ_В_Скобках]`,
и тест назовёт его по имени.

## Шаблон переноса

### 1. Разметка

Добавьте пространство имён в шапку вьюхи:

```xml
xmlns:loc="clr-namespace:CVPN.Localization"
```

Замените текст ключом:

```xml
<!-- было -->
<TextBlock Text="Маршруты" />
<Button Content="Добавить" ToolTip="Добавить правило" />

<!-- стало -->
<TextBlock Text="{loc:T Routing_Title}" />
<Button Content="{loc:T Common_Add}" ToolTip="{loc:T Routing_AddHint}" />
```

Подсказки-плейсхолдеры в полях ввода - это `Tag`, они переводятся так же.

### 2. Код

```csharp
using CVPN.Localization;

// было
Shell.Notify($"Профиль «{name}» создан");

// стало
Shell.Notify(Loc.T("Profiles_Created", name));
```

В ресурсах: `Profiles_Created` = `Profile “{0}” created`.

### 3. Ресурсы

Добавьте ключ в **оба** файла. Порядок в файле не важен, но держите его
одинаковым - так проще сравнивать.

### 4. Проверка

```
dotnet test --filter LocalizationTests
```

Три проверки поймают несоответствие: ключ отсутствует, перевод отстал,
подстановки разошлись.

## Соглашение об именах

`Раздел_Смысл`: `Logs_Title`, `Profiles_ImportFailed`, `Settings_LanguageHint`.
Общее для нескольких экранов - с префиксом `Common_`.

Не называйте ключи по тексту: `Common_Yes` переживёт смену формулировки,
а `Common_Da` - нет.

## Что переводить не нужно

**Строки лога.** Они начинаются с `[cvpn]` и попадают в файл, который
прикладывают к issue. Одноязычный лог читается всеми, а переведённый -
только автором. Разумнее перевести их разом на английский и не локализовать.

**Технические термины в интерфейсе.** `geosite`, `domain_suffix`, `rule_set`,
`TUN`, `sing-box` - это имена из конфигурации ядра, они одинаковы на всех
языках.

**Названия протоколов.** `vless · reality` и подобные приходят из модели
и остаются как есть.

## Смена языка на лету

Не поддерживается намеренно: потребовалась бы пересборка всего визуального
дерева или подписка на каждое разметочное расширение. Настройка сообщает,
что язык применится после перезапуска, - для приложения, которое обычно
висит в трее неделями, это приемлемо.
